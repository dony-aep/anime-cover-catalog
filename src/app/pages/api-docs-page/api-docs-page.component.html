GET /animes

Returns a paginated, filterable and sortable list of animes.

Query parameters

Query parameters for GET /animes
Parameter Type Default Description
qstring—Search across title, English and Japanese titles. Case- and accent-insensitive (roze finds Rozé). Max 100 characters.
genrestring—One genre or a comma-separated list (OR), e.g. Romance,Comedy. Case-insensitive; unknown values → 400.
themestring—One theme or a comma-separated list (OR), e.g. School. Case-insensitive; unknown values → 400.
demographicstring—One demographic or a comma-separated list (OR), e.g. Shounen. Case-insensitive; unknown values → 400.
typestring—One type or a comma-separated list (OR), e.g. TV,Movie. Case-insensitive; unknown values → 400.
yearinteger—Release year, e.g. 2024.
fieldsstringall fieldsComma-separated subset of fields to return, e.g. slug,title,genres. Unknown names → 400.
sorttitle | yeartitleField to sort by.
orderasc | descascSort direction.
pageinteger ≥ 11Page number.
limitinteger 1–10024Items per page (max 100).

Different parameters combine with AND; commas inside one parameter combine with OR — ?genre=Romance,Comedy&theme=School means (Romance OR Comedy) AND School.

GET /animes/random

Returns one random anime — ideal for "surprise me" or daily-pick features. Honors the list filters (q, genre, theme, demographic, type, year) and fields; responds 404 when no anime matches. Never cached (Cache-Control: no-store), so every request gets a fresh pick.

Limits & fair use

  • Pagination: limit is capped at 100 items per page (default 24). Use page to iterate.
  • Caching: responses are cached on Vercel's edge network (server-side — not your browser) via Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800: fresh for 24 h, then served stale for up to 7 days while it revalidates. The cache is invalidated on each deploy, so most requests never reach the function. /animes/random is the exception: never cached.
  • Conditional requests: every 200 response carries an ETag that changes only on deploy. Re-fetch with If-None-Match and you'll get 304 Not Modified with an empty body when nothing changed — free bandwidth for repeat clients.
  • Rate limit: traffic is rate-limited per IP (100 requests per minute). Above that you may receive 429 responses — cache on your side and use the edge-friendly patterns above and you'll never notice it.
  • CORS: open to any origin — safe to call from the browser.

Errors

All errors use standard HTTP status codes and share the same JSON shape, so you can handle them uniformly:

JSON
{{ '{' }} "error": "Anime not found: does-not-exist" {{ '}' }}
Error status codes
StatusWhen
200Success.
304Not modified — your If-None-Match ETag is still current; the body is empty.
400Invalid query parameter — e.g. limit above 100, an unknown fields name, or a genre/theme/demographic/type value that doesn't exist in the catalog (the message points you at /filters).
404No anime matches the requested slug, or no anime satisfies the filters passed to /animes/random.
429Rate limit exceeded (100 requests per minute per IP) — back off and retry.
